# 방법 개요 — 웨이퍼맵 결함 패턴의 혼동 구조 분석

**1쪽 요약 / 2026-09-11 / 학부 단독 연구 (KCS 2027 분과 Q 초록 접수 완료)**
상세 근거: `docs/decisions.md` (D-001~D-024)

> **주장 한 문장**: 정확도를 올리는 것이 목적이 아니라, **특징을 더할 때마다 어느 클래스 쌍이
> 병목이 되고 왜 이동하는지**를 특정한다.

**데이터** WM-811K 중 **라벨된 패턴 8종 25,519장**(`none` 제외). **분류기** 손설계 **특징 6종 + 단순 분류기**.
CNN을 쓰지 않는 이유는 질문이 *"무엇이 분리를 만드는가"*라서 **특징 하나씩의 기여를 읽어야** 하기 때문이다.

---

## 1. 분할 정책 — `lotName` 그룹 분할 (D-003)

**`StratifiedGroupKFold(5, shuffle)`, seed 0/1/2.** 층화는 라벨에만, **lot은 통째로 유지**.

- 같은 lot의 웨이퍼는 형제다. 무작위 분할이면 **test의 79.5%, `Edge-Ring`은 97.0%**가 train에 형제를 갖는다
- **클래스별로 나누지 않는다** — lot 10,762개 중 **4,204개(39.1%)**가 2개 이상 클래스에 걸친다
- ⚠ **이 분할은 표준이 아니다 — 조사한 8편 중 1편**이고 **원저자도 lot 단위가 아니다**(Wu 2015 §VI-A는
  lot이 아니라 **중복**을 통제했다). *"표준을 따랐다"*가 아니라 ***"소수파이며 누수를 재고 택했다"***가 맞다

## 2. 사전 등록 지표 — **accuracy를 보고하지 않는다** (D-002)

**per-class F1 + 혼동 쌍**만 쓴다. 클래스가 8:1 이상 불균형이라 accuracy는 다수 클래스로 올라간다.
판정 기준(대체 가능 < 0.01 등)은 **실행 전에 문서에 적고 시작한다.**

## 3. 결과 — 병목이 세 번 이동했다

| 단계 | 특징 | macro-F1 | 그 시점의 최대 병목 |
|---|---|---|---|
| 1 | 가장자리 3종 | 0.582 | `Center↔Loc` 0.188 |
| 2 | + 반경 2종 | 0.768 | `Loc↔Scratch` 0.168 |
| 3 | + 형상 1종 | **0.837** | `Edge-Loc↔Loc` 0.102 |

**주 분할 0.837 / 외부 검증 0.704**(항상 병기). 마지막 병목만 성격이 다르다 — 층별 대조비가
1층 1.81 → 6층 **1.07**로 수렴한다. `Edge-Loc` = `Loc` + 가장자리 구배이고, **구배가 연속이라
임계값이 없다**는 것이 현재 진단이다.

## 4. 이중 절제 — 순서와 대체 가능성을 따로 잰다 (D-023)

- **투입 순서** 3계열 × 3 선행 × 3 seed → **2/3(가장자리·형상) 순서 의존**, **1/3(반경)만 순서 무관**.
  그래서 초록에 ***"이는 이 투입 순서에서의 관찰이다"***를 넣었다
- **leave-one-out** 6종 **전부 대체 불가**(하락 0.018~0.098)
- **살아남은 것 하나**: *"반경 대조비를 더하면 `Center↔Loc`이 풀린다"*는 **9개 조합 전부에서 성립**한다

## 5. 교란 통제 — 분리가 의도한 물리량에서 오는가

방위각 지표가 잘 갈랐을 때 그것이 **대칭성 때문인지 불량 die 개수 때문인지** 구분되지 않았다.
**개수를 고정한 조건**과 **edge die 수로 층화한 조건**에서 다시 쟀고, 상당 부분이 개수 효과였다.
크기 축도 같은 방식으로 쟀다 — `size` 기여 +0.111 중 **84.3%는 반경 특징이 이미 가진 정보**였고
**잔여가 주 +0.017 / 외부 −0.023으로 이식되지 않아 `size`를 넣지 않았다.**

> ⚠ **「통제」와 「제거」는 다르다.** n을 20으로 고정한 것은 편향을 없앤 게 아니라 **n=20의 편향으로
> 고정한 것**이다. 이걸 혼동해 다른 검사에서 실제로 오진한 적이 있다.

## 6. 좌표계 진단 — ⬜ **설계만 했고 실행하지 않았다**

WM-811K에는 notch/flat 방향 정보가 없다. *"특정 각도에 몰린다"*는 ⓐ 위치 고정 ⓑ 좌표계 미정렬
둘로 읽히므로 **lot 내 / lot 간 2단 검사**를 설계해뒀다(`docs/coordinate_alignment.md`). **미실행이다.**
각도 지표를 회전 불변량으로만 설계해 **특징 설계에는 영향이 없고**, 이 진단은 *"notch 해석을 해도
되는가"*만 결정한다.

**9/10에 처음 실측한 것**: 8개 이면군(회전·플립) 변환에서 **6종 중 4종만 오차 0**, **2종 불합격**이다.
하나는 고쳤고(11월 적용), `circular variance`는 bin 경계 동점이라 **구조적으로 못 고친다**.
**보고 수치는 안 바뀐다**(입력을 회전시키지 않는다) — 바뀌는 건 *"6종은 회전 불변량"*이라는 **주장의 범위**다.

## 7. 선행 연구 대비 — 한 줄

WM-811K 선행 8편을 읽었다. **정규화는 원논문부터 있다** — 없는 것은 **「교란의 실측」이지 「정규화」가
아니다.** 8편 중 **교란을 측정해 보고한 연구 0편**, **accuracy를 헤드라인으로 쓴 연구 6편**이다.

## 8. 알려진 한계 — 검토를 받고 싶은 지점

1. **CNN 비교군이 없다.** *"모델 용량 문제가 아니다"*를 **부정할 근거도 없다**
2. **외부에서 갈리는 클래스가 있다** — `Donut` F1 주 0.737 / **외부 0.415**(외부 test 146장)
3. **반경 3등분 `R1=1/3, R2=2/3`은 임의값**이다. 성능으로 고르지 않았다는 것만 보장되고
   **물리적 근거가 비어 있다.** 대응은 스윕 곡선 병기뿐
4. **중복 웨이퍼맵 93그룹(0.58%)이 전부 lot을 넘어** 그룹 분할로 안 막힌다. 제거해도 Δ +0.0010
   (방향도 반대) — *"이 규모에서는 검출되지 않는다"*까지가 전부다
