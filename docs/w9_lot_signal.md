## 1. 문제 — 로드맵 §6 표의 넷째 열은 **전부 내 예측이고 한 번도 안 쟀다**

`planning/로드맵/…v4.8.md` §6 「패턴 ↔ 공정 원인 매핑」은 열이 넷이다.
**앞의 셋**(패턴 · 공간적 특징 · 유력한 공정 원인)은 관찰이거나 문헌인데,
**넷째 「후보를 좁히는 신호」는 2026-08-05에 쓴 예측이 그대로 남아 있다.**

| 패턴 | 넷째 열의 예측 | 이 문서가 거는 검사 |
|---|---|---|
| Center | lot 내 재현 → 장비 고정 이슈 | **①** |
| Edge-Ring | lot 전체에서 링 반경·폭 일관 → 챔버 조건 | **①** + **③**(`rc`·`mp`·`ctr`) |
| Edge-Loc | 집중도의 lot 내 일관성 | **①** + **③**(`cv`) |
| Donut | 피크 반경의 재현성 | **③**(`mp`) |
| Loc | **`waferIndex`(슬롯) 상관** | **②** |
| Random | **lot과 무관하게 균일** | **①②③의 음성 대조** |

표 아래에 **내가 직접 그어 둔 한계선**이 있다:
*"장비·시간 메타데이터가 없다. 검증 가능한 신호는 **lot 내 재현성 · `waferIndex` 상관 ·
방위각 집중도** 셋뿐"*. **셋째는 D-050·D-051에서 전수로 끝냈다.**
→ **#2 = 남은 둘 + 그 둘의 특징값 판(③)**이다.

⚠ **이 열은 「실행도 폐기도 안 된 채 방치된 사전 등록」이다** — D-023이 `F1+F3 vs F1`을
폐기한 이유와 같은 상태다. **재든 안 재든 기록이 남아야 같은 실패가 아니다.**

### 1-A. 이 측정이 **못 하는 것**을 먼저 박는다

- ⛔ **셋째 열(공정 원인)은 열리지 않는다.** D-044: 패턴↔공정 원인은 **측정한 문헌 0편**이고
  Wu 2015 원논문에 공정 용어가 전수 0회다. 로트 응집이 나와도 말할 수 있는 것은
  *"같은 lot의 웨이퍼가 같은 것을 겪는다"*까지이고 **「CMP 압력」은 외부 공정 정보가 있어야 붙는다**
- ⛔ **라벨 선별 편향과 갈리지 않는다.** 라벨은 811,457장 중 **172,950장(21.3%)**뿐이고
  **전문가 선별본**이다(D-024). 선별이 lot 단위로 이뤄졌다면 응집은 **선별의 성질**이다.
  → D-036의 `not_identifiable`과 **같은 벽**이다. **음성 대조(`Random`)가 부분적으로만 가른다**
  (선별 효과라면 클래스와 무관하게 오를 것이므로). **부분적이라고 적는다**
- ⛔ **슬롯 번호의 물리적 방향을 모른다.** `waferIndex` 1이 카세트 상단인지 하단인지
  자료에 없다. → **「상단 슬롯 편중」은 어느 쪽으로도 못 쓴다. 「편중이 있다」까지다**

## 2. 방법

**자료**: 라벨 보유 **172,950장 · lot 10,762개**(9종, `none` 포함). `waferIndex`는 **1~25**이고
전체 주변분포가 거의 평탄하다(슬롯별 6,854~6,968장). **분류기를 쓰지 않으므로 sklearn 축이 없다**
— D-047의 버전 의존은 이 측정에 걸리지 않는다. 특징은 채택판 캐시(`shape2_tienan.npz`)를 쓴다.

> **왜 `none`을 넣는가**: 묻는 것이 *"같은 lot이 같은 패턴을 다시 내는가"*이므로
> **`none`인 동료 웨이퍼는 진짜 「재현 안 함」**이다. `none`을 빼면
> *"패턴 둘이 있을 때 같은 패턴인가"*라는 **다른 질문**이 된다.

### ① lot 내 재현성 — 클래스 동시발생

lot `l`의 라벨 웨이퍼 수 `n_l`, 그중 클래스 `c`인 수 `n_{l,c}`.

```
R_c = Σ_l n_{l,c}(n_{l,c} − 1) / Σ_l n_{l,c}(n_l − 1)
```
= *"같은 lot에서 아무 동료를 하나 뽑았을 때 그것도 `c`일 확률"*.

- **귀무**: 전체 172,950장의 **클래스 라벨만 섞는다**(lot 소속 고정). `B=999`.
  **lot 크기와 클래스 주변분포가 정확히 보존**되므로 §3-2의 부수 변수(lot 크기)가 통제된다
- **구간**: `R_c`의 **lot 블록 부트스트랩** `B=2,000`. `Edge-Ring`은 lot당 9.0장이라
  **`deff`가 크다**(D-050에서 방위 기각률이 16.20이었다) — **Wilson/이항을 쓰지 않는다**
- 보고: `R_c` · 귀무 평균 `R_c⁰` · **응집 배수 `R_c / R_c⁰`** · 순열 `p` · lot 블록 95%

### ② `waferIndex`(슬롯) 상관

- **귀무**: **lot 안에서** 라벨 웨이퍼의 슬롯 번호를 섞는다. `B=999`.
  lot의 클래스 구성과 **점유 슬롯 집합이 둘 다 보존**된다
- 기대도수는 해석적으로 구한다: `E_{c,s} = Σ_l n_{l,c}·1[s ∈ slots(l)] / n_l`,
  통계량 `T_c = Σ_s (O_{c,s} − E_{c,s})² / E_{c,s}`. 방향은 **평균 슬롯의 기대 대비 편차**로 따로 낸다
- 🔴 **검출력이 ①의 결과에 반비례한다 — 미리 적는다.** lot이 단일 클래스로 채워져 있으면
  lot 안 순열이 움직일 것이 없다. → **「섞인 lot 안의 웨이퍼 수」(유효 표본)를 클래스마다 같이 낸다.**
  이 수가 작으면 `T_c`가 비유의여도 **「슬롯 무관」이 아니라 「못 잰다」**다

### ③ 특징값의 lot 내 일관성

클래스 `c`의 웨이퍼만 쓰고, 그 클래스 웨이퍼를 **2장 이상 가진 lot**에서
특징 `f`의 **급내 상관** `ICC_f,c = 1 − SS_within / SS_total`.

- **귀무**: 클래스 `c` 안에서 **웨이퍼를 lot에 재배치**(lot별 장수 보존). `B=999`
- 🔴 **부수 변수는 웨이퍼 크기다** (§3-2). 같은 lot은 같은 제품이라 **맵 크기가 같고**,
  특징 6종은 크기와 상관이 있다(D-015: `cov` −0.457 · `F1a` +0.264 · `F1b` −0.259).
  → **`size`(유효 die 수) 자체의 ICC를 먼저 내고**, 각 특징은 **클래스 내 `log size` 선형 잔차**
  위에서 **다시 낸다**. **원값과 잔차값을 둘 다 보고한다** (§3-6 — 보정 전후를 모두 본다)
